neuralzip · how it works

Compression is prediction. A better predictor is a smaller file.

Input
byte xt
one at a time, with everything before it
Expert 1 · context model (PPM)
Counts what followed the last 0–24 bytes; Witten–Bell escapes blend the orders.
pk = (nk(x) + ek·pk−1(x)) / (Nk + ek)
Expert 2 · GRU, trained online
128 hidden units, random init. Every 16 bytes: BPTT + one Adam step.
ht = GRU(ht−1, xt−1) · p = softmax(Woht)
Geometric mixer
Log-linear blend; weights learned by gradient descent on the code length. Can be sharper than either expert.
p(x) ∝ Πi pi(x)wi
Arithmetic coder
Spends exactly the information the model didn't already have.
bits = −log2 p(xt)
Why nothing else is transmitted
After each byte, every expert and the mixer update from the byte that actually arrived. The decoder sees the same bytes in the same order, so it runs the identical computation and rebuilds the same weights. The archive is the coded bits, a 4-byte magic, a length and a CRC — no model.
Shannon's bound, made concrete
Total file size ≈ Σt −log2 p(xt) + 2 bits. Lower cross-entropy is not a proxy for compression; it is compression.
